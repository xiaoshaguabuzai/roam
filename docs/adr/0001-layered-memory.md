# ADR-0001：记忆采用分层压缩，而不是每轮全量重放

- 状态：已采纳（2026-11-12）
- 背景：最初的产品设想是「同一会话每次把全部内容拿出来，让免费助手总结压缩后写回数据库」。
- 决策：保留「全部入库 + 摘要回库」，但改为 **L0 原文永存 → L1 分段摘要 → L2 会话滚动摘要 → L3 事实** 的分层结构，
  压缩在阈值/空闲时异步触发；「全量会话总结压缩」作为 L2 的 consolidate 作业定期执行。
- 理由：
  1. 全量重放是 O(n²) 输入。E4 模拟中 200 轮的全量重放累计约 106 万 token，分层方案为 10.5 万（9.9%）；
     真实会话每轮 150 token 时差距更大，网页通道会先触发限流。
  2. 「摘要的摘要」每轮叠加会持续漂移，且无法定位错误来源；分层结构保留 L0 与 L1 的区间映射，可重建、可审计。
  3. 事实（L3）单独抽取并带 `source_msg_ids`，让「记错了什么、从哪来的」可追溯。
- 代价：实现复杂度上升；需要处理压缩幂等、失败重试、重建。
- 备选方案：每轮全量重放（成本不可接受）、纯 RAG 无摘要（丢失跨轮叙事）、纯摘要无原文（不可审计）。

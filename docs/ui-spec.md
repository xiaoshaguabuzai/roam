# UI 规格：对齐 DeepSeek Harness

目标：交互与视觉按 DSH 高仿，而不是「看起来像聊天软件」。

## 1. 参考来源

- DSH Web 前端构建产物：`app.asar` 内 `@deepseek-ai/dsh-web-frontend/dist/assets/index-*.css`
- 运行中的 DSH 窗口截图（1296×828）逐像素取色
- 结构对照：左侧栏 / 中间对话 / 右侧面板，三段式布局

## 3. 布局

```
┌────────────┬──────────────────────────────┬──────────────┐
│ Sidebar    │ Chat                          │ Memory       │
│ 264dp      │ flex                          │ 360dp        │
│ #F9FAFB    │ #FFFFFF                       │ #FFFFFF      │
└────────────┴──────────────────────────────┴──────────────┘
```

- 断点：`≥1000dp` 记忆面板常驻；`760–1000dp` 记忆面板为右侧抽屉；`<760dp` 隐藏侧栏。
- 消息列最大宽 780dp，左右内边距 40dp。

## 5. 交互

- `Enter` 发送、`Shift+Enter` 换行；空输入时发送键置灰。
- 生成中发送键变停止态，消息流带 `▍` 光标逐字输出。
- 新消息自动滚到底部。
- 切换会话重新加载消息、清空轨迹。
- 记忆面板：`立即压缩`、`从原文重建`。
- 窄屏点右上角文件夹，记忆抽屉从右侧滑入（300dp、左侧 16dp 圆角、带遮罩）。

## 6. 移动端适配（1080×2400 真机实测）

| 问题 | 处理 |
|---|---|
| 记忆面板一进 App 就展开 | 默认关闭；仅 `≥1000dp` 自动展开，窄屏必须手动打开 |
| 状态栏把内容顶进系统栏 | 根容器 `windowInsetsPadding(systemBars)`；输入区 `imePadding()` |
| 状态栏图标白底不可见 | `isAppearanceLightStatusBars/NavigationBars = true` |
| 底部状态行折成两行 | 窄屏收敛为「N 条 · X tok」+「L1 · L2」 |
| 头部拥挤 | 窄屏隐藏「记忆引擎就绪」文案，只保留绿点 |
| 抽屉过宽 | 300dp + 左侧圆角 + 滑入动画 |

## 7. 模型与登录

- 入口：输入区上方「本地骨架 · 未接模型」→ 弹出「模型与登录」。
- 列出的通道：豆包网页、千问网页，各带登录按钮与地址。
- Android：内置 `LoginActivity` 的 WebView 打开站点，手动登录；Cookie 持久化在应用数据目录，
  下次由 WebViewDriver 复用；UA 去掉 `; wv` 标记。
- 桌面：调用系统浏览器打开同一地址。
- 登录完成后仍需 M1-3 的通道适配器才能真正答题，界面已注明「仅完成登录动作」。

### 已接入（M1-3）

- `DoubaoWebDriver` 在应用内常驻 WebView，复用登录 Cookie；`status()` 判定是否已登录，
  已登录时输入框上方的 chip 显示「豆包网页」，未登录显示「豆包网页 · 未登录」。
- 发送流程：注入脚本写入 contenteditable → 点击 `send-btn-wrapper` 发送 → 每 500ms 轮询
  `.message-list` 文本 → 去噪（时间行、`搜索 N 个关键词…`、提问回显）→ 以完整快照回调 UI。
- 真机验证：[phone-real-answer.png](evidence/phone-real-answer.png)（助手头部显示「豆包网页」）。
- 失败降级：未登录走本地骨架并提示；验证码提示手动完成；120s 超时报错。

## 8. 应用图标
